# סורק אבטחה לחבילות קוד - Multi-Agent

## רקע

רוב המפתחים לא מודעים לאיומי אבטחה שמגיעים דרך חבילות צד שלישי וקוד פתוח.
הכלים הקיימים מסורבלים, דורשים הטמעה ב-CI/CD ומייצרים הרבה התראות שווא.
קשה להבין מה באמת דורש תיקון ומה סביר להשאיר.

## מה המערכת עושה

1. מקבלת קובץ תלויות (requirements.txt, package.json, go.mod ועוד), קישור לריפו ב-GitHub, או שם של חבילה ומוצר בודדים (למשל wordpress 6.2).
2. מצליבה כל חבילה מול מאגר הפרצות הרשמי [NVD](https://nvd.nist.gov/), ו-Claude בודק אם הגרסה באמת נמצאת בטווח הפגיע ומחפש סיכונים נוספים.
3. מפיקה דו"ח מתועדף בעברית: מה חמור, למה זה חמור בהקשר של הפרויקט הספציפי, לאיזו גרסה לעדכן, וממה אפשר להתעלם.
4. מאמתת את הדו"ח מול מודל AI שני כדי להגביר את האמינות.
5. מציעה צ'אט לשאלות אבטחה חופשיות, התייעצות על CVE ספציפי וחיפוש חלופות לחבילות לא מאובטחות.

## הסוכנים

| סוכן | קובץ | תפקיד |
|------|------|-------|
| מתאם (Coordinator) | `agents.py` | מקבל את הבקשה ומנתב לסוכן המתאים |
| סורק חבילות (PackageScannerAgent) | `agents.py` | קורא את קובץ התלויות ומצליב מול NVD |
| אנליסט CVE (CVEAnalystAgent) | `agents.py` | בונה דו"ח מתועדף (Claude) ומאמת אותו (ChatGPT) |
| יועץ שיחה (AdvisorAgent) | `agents.py` | עונה על שאלות חופשיות ומושך נתוני CVE בזמן אמת |

```
קובץ תלויות ──► מתאם ──► סורק חבילות ──► NVD
                  │                         │
                  │                         ▼
                  │                  אנליסט CVE ──► Claude Opus 5.5 (דו"ח)
                  │                         │
                  │                         └────► ChatGPT 5.6 (אימות מוצלב)
                  │
שאלה חופשית ──────┴──► יועץ שיחה ──► Claude Opus 5.5 (+ נתוני NVD)
```

## שני מודלים

- **Claude Opus 5.5** (`claude-opus-5-5`): המודל הראשי שמייצר את הדו"ח ואת תשובות הצ'אט.
- **ChatGPT 5.6** (`gpt-5.6`): מקבל את נתוני ה-NVD הגולמיים ואת הדו"ח, ומחזיר הערות: אי דיוקים, פרצות שפוספסו ותעדוף שגוי.

בלי מפתח OpenAI המערכת עדיין עובדת, רק בלי האימות המוצלב.

## פורמטים נתמכים

| שפה | קובץ |
|-----|------|
| Python | `requirements.txt`, `Pipfile` |
| JavaScript / Node | `package.json`, `package-lock.json` |
| Go | `go.mod` |
| Java | `pom.xml`, `build.gradle` |
| Rust | `Cargo.toml` |
| PHP | `composer.json` |
| Ruby | `Gemfile` |

כדי להוסיף פורמט חדש, כותבים פונקציה ב-`parsers.py` שמחזירה רשימה של `(שם, גרסה, מאגר)` ומוסיפים אותה למילון `PARSERS`.

## התקנה והרצה

דרישות: Python 3.10 ומעלה.

```bash
pip install -r requirements.txt
```

מעתיקים את `.env.example` לקובץ `.env` וממלאים את המפתחות:

```
ANTHROPIC_API_KEY=...   # חובה
OPENAI_API_KEY=...      # מומלץ, לאימות מוצלב
NVD_API_KEY=...         # אופציונלי, מאיץ את הסריקה
```


הרצה:

```bash
python app.py
```

הממשק נפתח בכתובת http://127.0.0.1:7860

## איפה משיגים מפתחות

- Anthropic: https://console.anthropic.com/
- OpenAI: https://platform.openai.com/api-keys

עם מפתח, כל חבילה לוקחת פחות משנייה.

## מה בודקים בפרויקט

**שאלת המחקר:** האם פיצול לסוכנים מתמחים נותן ניתוח מדויק ומועיל יותר מפנייה בודדת למודל?

הצעה לניסוי בכיתה:
1. סורקים את `samples/requirements.txt` דרך המערכת.
2. מדביקים את אותו קובץ ישירות לצ'אט של Claude או ChatGPT, עם הבקשה "מצא פרצות אבטחה".
3. משווים בין התוצאות:
   - האם מזהי ה-CVE אמיתיים, או שהמודל המציא אותם?
   - האם הגרסאות המומלצות נכונות?
   - כמה התראות שווא יש בכל אחת מהתוצאות?
   - האם הקשר הפרויקט השפיע על התעדוף?
   - מה תפס האימות המוצלב?
